# ViiOS 0.4.0 — Server management and Feature Guide

This preview release brings the completed server-management work and the in-app feature booklet into the standalone distribution. The interface remains Turkish; English is the default documentation language.

## Included

- Server Monitor: system overview, memory/swap, disk and network rates, uptime and top processes.
- Process Manager: search, sort, details, protected-process rules and identity-checked termination.
- Services: search, filtering, details, allowlisted lifecycle/startup changes and bounded Linux journal output.
- Storage: physical disks, partitions, mounted-volume relationships and per-device I/O. Filesystem totals remain distinct from device-layer capacities.
- Feature Guide: 23 tool chapters in five categories, full-text search, step-by-step use, capability notes, related chapters and guarded application launch.
- Desktop: management-tool shortcuts, themed icons, responsive Dock pages with magnification, and removal of the large central lock/desktop wordmark.
- GitHub Pages: synthetic overview, processes, services and disk topology, with mutations disabled and no real server connection.
- Optional Windows Server Lab: restricted loopback SSH integration, disposable process/service fixtures and sample files. No host records or generated credentials are shipped.

## Upgrade

1. Back up your private `data/` directory (or configured `DATA_DIR`), including its encryption key and connection records. Never upload that backup.
2. Stop your existing controller, replace the application source, run `npm ci` and `npm run build`, then start it using your existing configuration. Keep the private data directory.
3. Existing remote helpers need updating through **Servers → Edit → Save and reconnect** to expose the new process/service/topology functionality. Controller source replacement alone does not update remote agents. Review the target and installation permissions before reconnecting.
4. Open **Özellik Rehberi** from the ViiOS menu. Normal controller startup uses port 3180; `npm run lab` is a separate opt-in Windows test environment on port 3280.

## Validation and scope

Local validation includes 208 Node tests, TypeScript/lint checks, production and static-demo builds, Python fixture/packaging checks and Windows helper tests. Browser checks cover the booklet, desktop integration and the synthetic preview. See [validation history](../validation.md) and the commit's GitHub Actions for exact results.

Live Windows measurements and the restricted local SSH fixture have been exercised. Real Windows service changes use isolated test doubles in local validation; the lab service is a disposable process fixture, not a host SCM service. Linux parsing and safety rules have fixture tests; a complete live Linux/systemd deployment and a production Windows OpenSSH bootstrap remain separate integration checks. Docker image execution is not verified by this release. This remains a **preview**, not a claim of complete production-platform certification.

## Source package and license

The reviewed source ZIP contains no administrator records, server inventories, SSH credentials, private keys, runtime data, local logs, screenshots or AI-tool session files. It includes a per-file SHA-256 manifest; a separate SHA-256 file verifies the archive.
